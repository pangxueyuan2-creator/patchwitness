# OpenAI Codex for Open Source readiness

## Current decision

**NOT READY TO APPLY**

The live, source-linked scorecard is maintained in [`../OSS_READINESS.md`](../OSS_READINESS.md).
This page explains the re-evaluation policy; it must not be used as a substitute for current data.

As of the initial v0.1.0 release, PatchWitness has no verified public stars, forks, external
contributors, package downloads, dependents, external mentions, issue/PR community, or production
adoption. Creating or implying those signals would be dishonest.

The [official OpenAI Codex for Open Source application](https://openai.com/form/codex-for-oss/)
states that maintainers of active open-source projects can apply and that review considers meaningful
usage, broad adoption or ecosystem importance, repository usage, and evidence of active maintenance.
The form asks for signals such as GitHub stars, monthly downloads, and why the project matters.

## Re-evaluation checklist

Record only source-verifiable data:

- GitHub stars and forks;
- unique external contributors;
- release/package downloads;
- dependent repositories or integrations;
- substantive issues and pull requests;
- maintained releases and commit activity;
- external articles, talks, or community mentions;
- documented use by real teams or open-source projects;
- maintainer work in review, issue triage, releases, and security response.

## Minimum internal bar before reconsidering

There is no official numeric threshold, so these are project-maintainer criteria, not OpenAI rules:

1. at least two maintained releases after v0.1.0;
2. at least three independent external contributors or integrations;
3. evidence of recurring use outside the maintainer's repositories;
4. active issue/PR maintenance over multiple months;
5. a credible explanation of ecosystem importance backed by links and metrics;
6. a concrete plan for API credits in PR review, maintainer automation, release workflows, or core
   OSS work.

When these conditions are met, refresh all figures live, cite their sources, and draft the 500-character
application answers. Until then, improve the project rather than optimize for an application.
