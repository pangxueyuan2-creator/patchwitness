# PatchWitness v0.3.0

This public alpha release packages the verification and Safe Delivery improvements
since v0.2.2. It helps maintainers inspect the scope and recorded checks of
coding-agent changes without asking a model to certify its own work.

## New and improved

- Check capture now has byte and time limits. Zero child exit does not pass a
  check whose output overflows or whose inherited pipes never close.
- Offline evidence loading rejects duplicate keys, non-finite numbers, symlinks,
  oversized inputs and observed file changes during reading.
- Git evidence handles protected renames, Unicode paths, staged-only changes,
  index/worktree disagreements and verification-time source or HEAD movement.
- The optional `patchwitness-safe-delivery` CLI consumes pinned TaskToPR v1/v2
  handoffs, with reviewer-selected plan approval and version/schema requirements.
  Missing independent checks or reviews stay incomplete.
- Windows contributors can run `python scripts/release_check.py` without Make.
  It exercises separately installed wheel and source distributions as consumers.

## Upgrading from v0.2.2

Checks are non-interactive and capture up to 1 MiB **per stream**. For larger logs,
configure a concise stdout/stderr summary and write full logs to a separately
reviewed file. Overflow and timeout fail closed and discard partial diagnostics;
see [check execution](../check-execution.md) for exact cleanup and exit semantics.

Evidence-file consumers accept regular UTF-8 JSON files up to 16 MiB. Copy symlink
targets to ordinary files. Regenerate oversized evidence for a smaller scope;
editing or truncating an existing file invalidates its digest. See the
[evidence format](../evidence-schema.md) for input and consistency boundaries.

Evidence v1 fields and canonical digest format remain. Existing contracts still
apply, with stricter handling of ambiguous paths, conflicting Git content and
untrusted clean-room executable resolution. These checks may expose changes that
older versions incorrectly accepted; review and fix the cause rather than
weakening a policy to regain a green result.

The deterministic core has zero runtime dependencies. Safe Delivery is optional;
the normal `patchwitness` commands do not require TaskToPR.

## Try the behavior

From the source checkout:

```bash
python demo/run_demo.py
python demo/run_bounded_checks.py
```

The first demo blocks a protected workflow change despite passing tests. The
second checks quiet and overflowing output in normal and clean-room modes, then
verifies each generated Passport. Both use temporary synthetic repositories.

## Limits

This is a public alpha, with no external production adoption claimed. Clean-room
worktrees are not a hostile-code sandbox. Process cleanup cannot guarantee
containment of detached descendants. File consistency checks are best-effort,
not atomic filesystem snapshots. A digest verifies normalized content, not its
author or approval. A passing command does not prove semantic correctness.

Copilot CLI's real Windows `sessionEnd` dispatch remains unverified; direct
PowerShell hook tests do not establish that compatibility.
