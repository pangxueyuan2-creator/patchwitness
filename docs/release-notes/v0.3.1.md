# PatchWitness v0.3.1

This maintenance release packages the reliability fixes merged after v0.3.0.
Existing v0.3.0 assets are unchanged; install v0.3.1 to receive these fixes.
The deterministic core still has no runtime dependencies. Evidence v1 fields
and canonical digest rules remain unchanged.

## Upgrade from v0.3.0

- Use actual TOML booleans and arrays in policy files. Quoted `"false"`, scalar
  path lists and other mistyped known fields now fail before checks execute.
  Correct the policy and rerun verification; do not reuse approvals based on
  coerced values. See [contract migration](../contracts.md).
- MCP callers must send an explicit JSON boolean `true` to execute checks.
  Invalid argument types, duplicate JSON keys, invalid UTF-8 and oversized
  input lines are rejected. Notifications do not dispatch tools. See
  [input boundaries](../input-and-git-evidence.md).
- Rerun affected clean-room checks. Git display prefixes and textconv must not
  substitute different candidate bytes, and masked index entries now fail
  closed. Default hook suppression also applies to check subprocesses, though
  explicit child overrides remain possible. See [candidate fidelity](../clean-room-fidelity.md)
  and [patch paths](../clean-room-patch-paths.md).
- Review prior results using wildcard directory prefixes in allowed, denied or
  protected paths and rerun with the corrected [glob semantics](../rules.md#path-pattern-semantics).
- Git display settings no longer hide untracked candidate dirt or submodule
  changes from collection. Literal paths, line counts and streamed batch
  responses retain their identities. See [visibility limits](../git-visibility.md).
- Checks that change additional tracked or staged paths now cause PW032.
  Newly created unstaged outputs remain outside the recorded scope; stage
  intended generated changes before capture. See [check execution](../check-execution.md).
- Regenerate SARIF reports when filenames contain URI-special characters.
  `executionSuccessful` describes completed analysis, not gate approval: use
  the verified Passport status and trusted policy for decisions. See
  [SARIF consumer migration](../sarif-paths.md).

## Install the release wheel

Use an isolated environment or tool installer. For example:

```bash
uv tool install --force "https://github.com/pangxueyuan2-creator/patchwitness/releases/download/v0.3.1/patchwitness-0.3.1-py3-none-any.whl"
patchwitness --version
patchwitness doctor
patchwitness scan --no-checks
```

The expected version is `0.3.1`. Inspect repository-owned commands before
enabling checks. GitHub release assets include a source distribution,
`SHA256SUMS.txt` and build-provenance attestations. A GitHub release does not
imply publication to PyPI.

## Limits

This remains a public alpha. Maintainer-run regressions and hosted CI are not
independent adoption or human approval. Clean-room worktrees and Git hook
suppression are not hostile-code sandboxes. Consistency checks are best-effort,
not atomic snapshots. Submodules are not recursively verified, and POSIX
backslash/non-UTF-8 collection retains documented limits. GitHub SARIF ingestion
and Copilot CLI's real Windows session-end dispatch remain separately unverified.
A valid digest or successful command does not establish semantic correctness.
